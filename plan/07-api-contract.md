# API Contract

Base path: `/api/v1`. Server: [server-podium](../server-podium).

This document has two parts:

- **Part 1 — Frozen.** Endpoints the Android transmitter already uses. These are
  live in production. **Do not change them.**
- **Part 2 — To build.** New endpoints for Bike Podium.

---

# Part 1 — FROZEN (Android transmitter depends on these)

These were read directly from the working server, not designed on paper. The
Android app is already built against them and cannot be changed, so the paths,
the JSON field names, and the response shapes are fixed.

If a refactor makes one of these hard to keep, **the refactor is wrong**, not the
endpoint.

## Authentication model

Google and SMS only answer *"who is this person"*. After a successful provider
check the server issues its **own** tokens, and every other route accepts only
those — never a Google ID token, never an OTP code.

```
Authorization: Bearer <accessToken>
```

- access token: JWT, default **15 minutes** (`JWT_ACCESS_EXPIRES_IN`)
- refresh token: opaque random value, default **30 days**
  (`JWT_REFRESH_EXPIRES_IN`), stored only as `sha256()` in
  `sessions.refresh_token_hash`, **rotated on every refresh**
- reusing an already-rotated refresh token no longer matches any session and is
  rejected
- `requireAuth` verifies the access token statelessly — signature and expiry only,
  no database or network call — and sets `req.auth = { userId, role, sessionId }`

### `GET /api/v1/auth/config`

Public. Clients call this before rendering the login screen and show only the
methods returned.

```json
{ "providers": ["GOOGLE", "SMS"] }
```

Controlled by the `AUTH_PROVIDERS` env var. A disabled provider's endpoints
return `403 { "error": "AUTH_PROVIDER_DISABLED" }` — deliberately not 404, since
the implementation is still there and only exposure is toggled.

### `POST /api/v1/auth/google`

```json
// request
{ "idToken": "<google-id-token>" }

// response 200
{ "user": { ... }, "accessToken": "...", "refreshToken": "...", "requiresProfile": false }
```

Verifies the token against `GOOGLE_CLIENT_IDS`, finds or creates the user.

### `POST /api/v1/auth/sms/request`

Rate limited: **10 per 15 min per IP**.

```json
// request
{ "phone": "+15551234567" }   // E.164

// response 200
{ "challengeId": 123 }
```

The code itself is only ever delivered by the SMS provider, never in the response.

### `POST /api/v1/auth/sms/verify`

Rate limited: **30 per 15 min per IP**.

```json
// request
{ "challengeId": 123, "code": "123456" }

// response 200 — same shape as /auth/google
```

Attempt-limited (`max_attempts`, default 5) and expiring.

### `POST /api/v1/auth/refresh`

```json
// request
{ "refreshToken": "..." }

// response 200
{ "accessToken": "...", "refreshToken": "..." }
```

Rotates in place. A deactivated user (`users.is_active = false`) is rejected here
as well as at sign-in.

### `POST /api/v1/auth/logout`

Requires an access token. Revokes that one session. The access token itself stays
valid until its own short expiry — the accepted trade-off of stateless
verification.

### `POST /api/v1/auth/logout-all`

Requires an access token. Revokes every session for that user, all devices.

### `PATCH /api/v1/users/me`

Requires an access token. Body: any of `firstName`, `lastName`, `nickname`,
`emergencyPhone` — all optional.

`emergencyPhone` is **not** required for `requiresProfile` to become `false`; the
other three are.

### `GET /api/v1/events/by-code/:code`

**Unauthenticated on purpose.** The transmitter looks the event up straight after
a QR scan or code entry, before the rider has necessarily signed in.

```json
// response 200
{ "eventId": "uuid", "name": "...", "type": "RIDE", "requiresBib": false }
```

404 if no active event has that code.

**Event code format:** `DDMMYYYY` + a letter suffix — `13082026A`, `13082026B`,
… `13082026Z`, `13082026AA`. Generated by
`server-podium/src/modules/events/event-code.ts`. Short enough to read aloud at a
start line.

### `POST /api/v1/events/join`

Requires an access token.

```json
// request
{ "eventCode": "13082026A", "bib": "42" }   // bib optional unless requiresBib

// response 200
{
  "eventId": "uuid",
  "participantId": 456,
  "eventName": "...",
  "eventType": "RIDE",
  "requiresBib": false
}
```

**Idempotent by upsert** — re-joining returns the existing participant row rather
than erroring, because the app retries after a network drop. It also clears
`leftAt`.

Returns 400 if the event requires a bib and none was given; 404 if the code
matches no active event.

`participantId` is `event_participants.id`. **This is the identifier the whole
tracking system hangs on** — the app stores it and sends it with every batch.

### `POST /api/v1/events/:eventId/locations/batch`

Requires an access token. **The main ingest endpoint.**

```json
// request
{
  "participantId": 456,
  "points": [
    {
      "lat": 32.0853,
      "lng": 34.7818,
      "accuracy": 8.5,
      "recordedAt": "2026-08-13T09:14:02.000Z",
      "emergency": false
    }
  ]
}

// response 200
{ "saved": 1 }
```

Constraints, all enforced today:

| Rule | Value |
|---|---|
| Points per batch | 1 to **200** |
| Request body limit | 100 kb (global `express.json`) |
| `lat` | −90 to 90 |
| `lng` | −180 to 180 |
| `accuracy` | optional, non-negative |
| `recordedAt` | coerced to a date; **device GPS time, not upload time** |
| `emergency` | optional, defaults to `false` |

The server verifies the participant belongs to **the calling user** *and* to the
event in the URL; otherwise 404 `Participant not found for this event`.

**Batching is what makes offline work.** A rider in a dead zone queues points
locally and uploads them in batches on reconnect. `recordedAt` preserves when the
rider was actually there, and the server stores `received_at` separately.

### `GET /health`

Public. `{ "status": "ok" }`. Never touches the database.

## Changes that are allowed to these endpoints

Additive only:

- ✅ adding a new **optional** request field
- ✅ adding a new field to a **response** (old clients ignore it)
- ✅ changing anything about how the server stores the data internally
- ❌ renaming or removing any request field
- ❌ changing a path or method
- ❌ making an optional field required
- ❌ changing the meaning of `participantId`

# Part 2 — TO BUILD

New endpoints. All require `Authorization: Bearer <accessToken>` unless noted.

## Conventions for new endpoints

**Response shape**

```json
{ "data": { ... } }
{ "error": "CODE", "message": "human readable" }
```

**Status codes — use real ones.**

| Code | Meaning |
|---|---|
| 200 | OK |
| 201 | Created |
| 400 | Bad input (zod validation failed) |
| 401 | No token, bad token, or expired token → client re-logs in |
| 403 | Valid token, not allowed → client shows "not permitted" |
| 404 | Not found |
| 409 | Duplicate — replayed offline action, returns the original result |
| 429 | Rate limited |
| 500 | Server fault |

> The example server in `examples/old-example servers/server a` follows a rule of
> *"never return anything except 200, and 500 only in a catch"*. **We deliberately
> do not follow it.** The PWA must tell 401 (re-login) from 403 (forbidden) from
> 409 (already applied), and the offline sync design depends on 409. This is a
> conscious rejection, not an oversight — do not "restore consistency" later.

**Offline de-duplication.** Every mutating request carries a client-generated
UUID:

```
X-Client-Action-Id: <uuid>
```

If the server has already applied that id it returns **409** with the original
result. The client treats 409 as success. See `client_actions` in
[02-database-schema.md](02-database-schema.md).

**Validation.** Every endpoint gets a zod schema in `<module>.schemas.ts`, matching
the existing pattern.

## Users

```
GET    /api/v1/users/me                   the signed-in rider's profile   ✅ built
```

Added for the web app: it starts with a stored session but knows nothing about the
rider until it asks. Same response shape as `PATCH /users/me`, including
`requiresProfile`. Additive, so Part 1 is untouched and the Android app is
unaffected. 401 if the token is valid but the user row is gone.

## Events

```
POST   /api/v1/events                     create
GET    /api/v1/events                     my events (?filter=upcoming|live|past|mine|joined)
GET    /api/v1/events/:eventId            detail (respects visibility)
PATCH  /api/v1/events/:eventId            edit            (owner)
DELETE /api/v1/events/:eventId            delete          (owner)
POST   /api/v1/events/:eventId/publish    draft -> published    (owner)
POST   /api/v1/events/:eventId/start      -> live               (owner/operator)
POST   /api/v1/events/:eventId/finish     -> finished           (owner)
GET    /api/v1/events/public              browse public events  (no auth)
```

`finish` also writes `participant_tracks` — see the retention rule; the raw-point
cleanup must never run for an event whose tracks were not written.

## Event members (roles)

```
GET    /api/v1/events/:eventId/members
POST   /api/v1/events/:eventId/members         add operator/viewer   (owner)
PATCH  /api/v1/events/:eventId/members/:id     change role           (owner)
DELETE /api/v1/events/:eventId/members/:id                           (owner)
```

## Participants

```
GET    /api/v1/events/:eventId/participants
POST   /api/v1/events/:eventId/participants          manual add       (owner/operator)
POST   /api/v1/events/:eventId/participants/import   Excel/CSV import (owner/operator)
PATCH  /api/v1/events/:eventId/participants/:id      edit / status    (owner/operator)
DELETE /api/v1/events/:eventId/participants/:id                       (owner/operator)
POST   /api/v1/events/:eventId/participants/:id/approve               (owner)
POST   /api/v1/events/:eventId/participants/:id/reject                (owner)
```

Status changes set one of `registration_status`, `attendance_status`,
`result_status` — never a single merged field.

Marking a finisher sets `result_status`, `finished_at` and `finish_position`.

## Routes

```
POST   /api/v1/routes                 create (upload or drawn)
GET    /api/v1/routes                 my routes
GET    /api/v1/routes/public          public library (paged, filterable)
GET    /api/v1/routes/:id             detail, full geometry
PATCH  /api/v1/routes/:id             rename, publish/unpublish   (owner)
DELETE /api/v1/routes/:id                                          (owner)
POST   /api/v1/events/:eventId/route  attach a route to an event  (owner)
```

`GET /api/v1/routes/public` supports `?place=&minDistance=&maxDistance=&minElevation=&maxElevation=&type=&page=&pageSize=`
and returns **`preview_points` only**, never full geometry — the browser shows
many map previews at once. See [08-routes-and-maps.md](08-routes-and-maps.md).

## Live tracking

```
GET /api/v1/events/:eventId/live       latest position of every rider
GET /api/v1/events/:eventId/live/:participantId    one rider's detail
GET /api/v1/events/:eventId/tracks     saved tracks (history)
GET /api/v1/events/:eventId/tracks/:participantId
```

`GET /live` reads **only** `participant_last_location` — never `location_points`.
It returns each rider's position, `recorded_at`, `emergency`, and distance
travelled.

**Polling first.** The PWA polls this endpoint. The contract is deliberately
shaped so it can be served by SSE or WebSocket later without redesigning
anything.

Riders with `emergency = true` are flagged in the response so the map can blink
them red. In v1 that is the only SOS behaviour — the name and `emergency_phone`
are deliberately not surfaced yet.

**All times in every response are UTC** (ISO 8601 with `Z`). Clients convert to
the viewer's local timezone for display. The server never sends a local time.

Visibility is enforced here: if `show_live_locations` is false and the caller is
not a member, this returns 403.

## Rate limiting

The global limit is **300 requests / 15 min per IP**.

⚠️ **This is wrong for the location endpoint.** Riders on mobile networks share
carrier NAT addresses, so at a large event many real riders appear as one IP and
get throttled as if they were attacking.

Fix: give `POST /events/:eventId/locations/batch` its own limiter keyed on
`req.auth.userId` rather than the IP address.
